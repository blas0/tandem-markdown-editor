# Design System: Tandem

## Overview

**Creative North Star: "A writing workspace"**

Tandem uses neutral application chrome around a continuous document. Open Runde, Coss controls, a scrolling navigation sidebar, and a floating review toolbar frame the document. Review decisions expose complete original and proposed text.

The Coss registry system replaces the earlier Mira/Blue, Radix, Reicon, and Lisse designs. [PRODUCT.md](PRODUCT.md) covers product requirements. This document describes the current source.

**Key Characteristics:**

- Coss neutral light and dark themes with semantic status and review colors.
- Direct Coss controls with 24 retained product compositions.
- A centered document within the space left by resizable sidebars.
- Supplied document and provider assets, Keyline glyphs, and the existing effort indicator.

Implementation evidence comes from `packages/ui/tokens.css`, the retained files under `packages/ui/coss/`, `packages/ui/primitives.tsx`, product stylesheets, and their consumers. See [the component outline](UI-COMPONENTS.md) for current ownership.

## Colors

The frontmatter records resolved CSS colors from the current token source and installed Tailwind palette. `dark-` entries document overrides selected by `data-theme="dark"`. Runtime CSS remains the source to consult when refreshing this record. The canonical Coss source is the [style registry](https://coss.com/ui/r/style.json).

### Primary

`primary` is neutral, with `primary-foreground` supplying contrasting text. Success, information, warning, and destructive colors identify status and actions with those meanings. Blue selection and information colors do not establish a Blue action theme. Chart variables remain the Coss preset; their presence does not add charts to the product.

### Neutral

Background, card, popover, and sidebar tokens separate the writing area from navigation and overlays. `muted` is a background; muted text uses `muted-foreground`. Dark background mixes neutral-950 at 95% with white; card and popover mix that background at 98% with white. Sidebar uses its separate 97% mix.

**The Coss styling Rule.** Use the copied registry variants and semantic tokens for controls. Keep product layout and motion separate from control styling.

Dynamic folder/document colors, custom hex values, and document formatting remain data. ColorPicker is a composition of Coss Popover, Button, Input, and Slider. It is not a second palette theme.

## Typography

Open Runde remains bundled at weights 400, 500, 600, and 700. Coss body and heading variables resolve to that family; code and keyboard hints use the mono stack. The frontmatter records the observed body, control, metadata, document, and onboarding headline roles. The control entry describes the desktop `sm` breakpoint; registry controls use base text sizing below it.

The document remains 16px/26px with a 66ch measure. Headings preserve user document hierarchy, including 30px/38px, 24px/32px, 20px/28px, and 17px/25px steps. User formatting changes document content without redefining application typography.

**The Readable comparison Rule.** Show complete Original and Proposed versions. Mark removals with strike-through and additions with underline as well as semantic colors.

## Layout

The workspace has Library, Symlinks, and Cadences navigation, a writing area, and a floating canvas review toolbar. Library contains Tandem-owned documents and regular folders. Symlinks projects active linked documents and linked directory roots from `linkedPath`, preserving their hierarchy and actions. Navigation uses a shared scroll container and 28px virtualized rows. All three sections preserve collapse state; label-adjacent chevrons expose expansion controls.

Default layout tokens are 216px navigation, 760px maximum document width, and a 44px titlebar. Navigation resizing persists its selected width. The native traffic lights and navigation toggle share one centerline. The document header and formatting toolbar meet at one continuous border in both themes and at wide and narrow widths. The document stays centered in the remaining writing area. Product CSS responds at 1100px, with a 700px onboarding-height rule. Coss responsive control sizing begins at Tailwind's 40rem `sm` breakpoint.

Spacing aliases follow Tailwind's quarter-rem unit. The normal document page uses 48px padding within a scroll area padded by 32px; narrow layouts adjust the writing space. These values describe product layout, not extra control variants.

## Elevation & Depth

Coss controls use their registry borders, translucent state fills, inset highlights, and shadows. Buttons and inputs retain distinct focus treatments; do not replace them with a universal custom ring. Cards use their registry border and subtle shadow. Popups use Coss popup styling and Base UI placement. The application and gallery roots are isolated for portals.

The sidecar records product shadow aliases and motion separately from frontmatter tokens. Sidebar collapse and its adjoining titlebar fill update immediately; drag resizing and persisted widths remain. The floating review toolbar remains mounted for its opacity and translation exit transition and then unmounts. Reduced motion skips its entry and exit motion. IconSwap transitions opacity, blur, and scale over 250ms. The declared 100ms/160ms token aliases do not replace the controls' own registry transitions.

## Shapes

Coss uses native CSS radii. The root radius is 0.625rem, with the derived small, medium, large, and extra-large steps recorded above. Registry Card uses Tailwind's 1rem `rounded-2xl` step. Extra-small buttons use the medium step; badges normally use the small step. Switch tracks and thumbs remain fully rounded.

Lisse, its SVG border painter, its PostCSS adapter, and the old 28px control-radius system are removed. Supplied document/provider artwork and glyph geometry remain assets; they do not define control corners.

## Components

**The Shared owner Rule.** Change a repeated control or composition at its shared owner. Screens supply data and actions through that owner.

### Controls and forms

Import plain controls directly from `packages/ui/coss/<component>`. Button variants are `default`, `outline`, `secondary`, `ghost`, `link`, `destructive`, and `destructive-outline`. Default means Coss default. Use `loading`; the old `primary`, `quiet`, `success`, and `busy` aliases are removed. Creation actions use default extra-small buttons, document actions use outline extra-small buttons, and icon-only sidebar actions use ghost buttons. Destructive actions use their documented Coss variants.

Trigger composition uses `render`. Select uses items and `onValueChange`; the product SelectField retains its labeled form callback. ToggleGroup values are arrays. Coss Field supplies associated labels and descriptions. Shared dialogs and menus preserve focus, disabled state, nested forms, Escape, and save shortcuts through Base UI and product handlers.

ColorPicker accepts a toolbar trigger. ToneSlider maps eleven positions to palette shades and exposes meaningful shade text through Slider's `getAriaValueText` forwarding. SwitchMenu preserves disabled triggers and options, provider grouping, effort icons, and multiple selection. SwitchField retains label/description association. StatusBadge combines an outline Coss Badge with a semantic status dot.

### Product interactions and assets

Document titles enter inline editing. Sidebar row actions open one surface instead of nested menus: a Name field that saves each keystroke, then export, duplicate, cadence, and the destructive archive or disconnect action; folder surfaces add the Color swatches, shade slider, and reset between Name and the destructive action. Moving and reordering items happens by dragging rows, not through menus. Tab moves focus only inside the editor and open popups; the sidebar draws no focus ring and its 24px row fills leave 4px between an active row and a hovered neighbor. Uncolored document, folder, cadence, and linked-directory icons inherit the shared navigation tint. An explicit item color replaces the tint. Linked folders retain their connection glyph and disconnect action. Archive is a list with document/folder filtering and restoration; tagging and its metadata controls are removed. Sidebar Settings uses the outline button variant and Archive uses destructive-outline.

The existing Review import flow preserves selectable read-only preview text and encoding selection before confirmation. CodeMirror owns the single Markdown editable view and reveals active syntax without modifying the source. Review diffs sit below their affected text in source order. The floating toolbar contains Annotate, model, effort, fast mode, and cadence controls with full-document review as the default. The cadence choice starts the request with the displayed invocation settings. The header Review actions menu owns bulk decisions. Completed unchanged, failed, and cancelled reviews retain explicit status text. Formatting controls retain selection, undo, and keyboard behavior; narrow layouts move secondary actions into overflow menus. Find retains focus and cycles matches. Annotation mode retains its crosshair, Escape cancellation, and review shortcut. Document zoom affects editor content.

ResizablePanel, IconSwap, InlineTitle, and DiffText have no direct Coss replacements. Supplied document SVGs, provider marks, app branding, Keyline action glyphs, and EffortIcon remain. The existing effort bars, selected-level colors, and ultra animation communicate effort state. Coss does not replace these assets. Keep their licenses in the existing notice files.

## Do's and Don'ts

### Do:

- Do use the Coss semantic tokens and registry variants in both themes.
- Do preserve user-selected colors, document formatting, supplied artwork, provider marks, Keyline glyphs, and EffortIcon.
- Do retain sidebar resizing, persistence, immediate synchronized titlebar updates, and reduced-motion behavior.
- Do keep complete review text, source-location actions, and non-color difference marks.
- Do inspect both themes, the component gallery, and narrow windows after shared UI changes.
- Do verify native Mac text and assistive workflows separately before claiming release readiness.

### Don't:

- Don't restore legacy Mira variants, Blue action overrides, Radix wrappers, or Lisse painting.
- Don't recreate removed document cards, tagging controls, or a second control theme.
- Don't introduce screen-local copies of shared controls.
- Don't replace user-authored colors or supplied product assets with theme tokens.
- Don't treat source inspection, historical captures, or earlier tests as validation of the current integration.
